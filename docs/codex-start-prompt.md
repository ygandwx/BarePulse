在已经连接 `ygandwx/BarePulse` 仓库、具有代码编辑能力的 Codex 任务中发送下文。提示词要求开始编码；不授予真实设备操作或生产部署权限。

---

请直接开始实现 https://github.com/ygandwx/BarePulse ，这是持续编码任务，不要只输出方案。

先读取 AGENTS.md、README.md、docs/development-workflow.md、docs/implementation-status.md 和 docs/development-plan.md；实现 PiKVM 时必须读取 docs/pikvm-integration.md。检查已有代码和 Git 状态，保留用户修改；已有实现就接着做，不从头重建。使用 codex/barepulse-implementation 开发分支，若当前已经是用户指定的开发分支则沿用。

目标是完成开发计划 M1–M5 的可运行首期代码、必要测试和文档，并完成 M6 中不依赖真实设备授权的离线验收与交付资料。第一批先打通“启动系统→管理员登录→录入服务器和设备→绑定端口→提交模拟电源任务→查询结果和审计”，随后自动继续流量、真实驱动代码、共享控制台和 WHMCS。按模块同步完成后端、前端、错误处理和测试。技术栈优先沿用 Go + PostgreSQL + Docker Compose，常规实现选择自行决定并记录。

持续按“实现→验证→修复→记录→提交→下一任务”推进。不要因为完成计划、骨架、某个模块或一次提交就停下来询问是否继续。适合并行的工作可以拆给子代理，但先约定接口和文件归属，由主任务集成验证。简短报告进度后继续工作。

局部缺少设备、凭据或外部环境时，记录阻塞，完成可行的模拟／契约测试并继续其它任务。不要编造协议、OID 或测试结果，不用 TODO、固定成功响应、静态页面或放宽断言冒充完成。代码实现、离线测试和实机验证分别记录。收费、超额限速／断网／断电等未确认策略做成配置且默认关闭。

沿用现有设备限制：当前只允许离线开发及本地模拟测试，不调用真实设备的 HTTP、SNMP、SSH、电源、端口切换或虚拟介质接口，不部署生产环境。真实设备访问默认关闭。不要绕过权限、审批或网络限制；这些限制只阻塞相关实机操作，不应阻塞其它开发。

重点保证服务归属与端口绑定校验、流量不重复入账、电源幂等与超时不盲目重试、PiKVM 整机独占、旧视频／键鼠／介质连接撤销，以及装机保护跨掉线和重启保留。

每个可审核增量更新 docs/implementation-status.md 并提交代码；有权限时推送开发分支、创建或更新 PR。不要强推、覆盖用户改动或删除分支。远端暂时不可写时继续本地工作并记录未推送内容。

除约定目标完成、我明确要求停止、所有剩余任务确实被必须由我解决的外部条件阻塞，或环境明确提示额度／运行限制外，不要主动提前结束。若能可靠读取剩余额度，接近用尽（例如约 10%）时先保存检查点再暂停；不能读取时不要猜测或声称正在监控。上下文压缩后继续从仓库记录恢复，不把它当作额度用尽。
