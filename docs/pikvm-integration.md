## 2. 设备与软件基线

### 2.1 硬件连接

手册描述一台带管理 CPU 的 16 口 KVM：后部端口 1–12、前部端口 13–16，每个被控节点组合连接包括开关机信号、USB 和 HDMI。管理面板与被控目标的控制台输出是不同用途。

用户明确这台设备由多台服务器共享，同一时间只能打开一个目标的远程控制台。因此必须把电源端口映射和整台 KVM 的共享控制台资源分别建模。

`online/offline` 表示端口连接或设备通电相关状态，不等于操作系统网络在线。`enabled/disabled` 表示是否允许端口设备开机；`ON/OFF` 才是手册中的节点开关机状态。

## 3. 调用链与源码定位

### 3.1 已核对的调用顺序

外部 HTTPS 请求先由 Nginx 将 `/api/...` 改写为 kvmd 内部路径；`HttpServer` 注册的 wrapper 调用 `self._check_request_auth()`，再进入装饰器绑定的处理函数。`KvmdServer` 覆盖基类检查方法并委托给 `api/auth.py`。

控制处理函数从查询字符串取 `num`，拼接固定的厂商程序名，使用 `subprocess.getstatusoutput()` 执行，再由 `make_json_response()` 包装结果。这条链说明鉴权会被调用，但不证明当前运行配置开启了认证。

## 4. 外部接口映射

以下方法与路径来自本机源码及 Nginx 静态配置。控制类 POST 的 `num` 位于 URL 查询参数，不能把仅含 `num` 的 JSON 请求体当成兼容调用。

| 功能 | 方法 | 外部路径 | 参数／底层调用 | 平台用途 |
| --- | --- | --- | --- | --- |
| 节点电源状态 | GET | `/api/node_status` | 无 `num`；`nodstatus` | 候选状态来源，需质量校验 |
| 端口数量和状态 | GET | `/api/chassis_type` | 写死 `num=16`；`sudo portstatus` | 连接、启用、电源状态观测 |
| 当前 KVM 目标 | GET | `/api/chassis_status` | `sudo kvmstatus` | 切换前后复核；须先检查 error |
| 节点开机 | POST | `/api/open_node` | 查询 `num`；`sudo portpwron <端口>` | 标准开机任务 |
| 节点关机请求 | POST | `/api/close_node` | 查询 `num`；`sudo portpwroff <端口>` | 具体按键／关机行为待验证 |
| 节点复位 | POST | `/api/reset_node` | 查询 `num`；`sudo portreset <端口>` | 计划按硬件复位暴露；实际电气行为待验证 |
| 禁用节点 | POST | `/api/disable_node` | 查询 `num`；`sudo portdisable <端口>` | 管理员维护，含强制关闭与禁止开机 |
| 允许节点开机 | POST | `/api/enable_node` | 查询 `num`；`sudo portenable <端口>` | 管理员维护，不等同立即开机 |
| 切换目标 | POST | `/api/kvm_node` | 查询 `num`；`sudo kvmswitch <端口>` | 仅由会话管理器在持锁时调用 |
| WebSocket | GET／Upgrade | `/api/ws` | 内部 `/ws` | 状态／键鼠等事件，具体事件需白名单 |
| 视频服务 | 按资源定义 | `/streamer`、`/streamer/...` | 反代 ustreamer | 实际资源与撤销方式待验证 |

这些是设备 API，不向客户直接开放。客户提交 BarePulse 服务器 ID 和标准动作，平台根据绑定解析端口，并限制为 1–16 的整数。

源码扫描还发现 HID、MSD、ATX、GPIO、Redfish、日志和设备配置接口。发现路径不等于已验证其语义；不将标准 ATX／Redfish 自动当作上述 16 口接口的替代品。

## 5. 返回值及解析陷阱

### 5.1 通用 JSON 封装

`make_json_response()` 的默认 HTTP 状态为 200，默认结构是 `{"ok": status == 200, "result": result 或空对象}`。控制函数没有因为厂商命令退出非零而主动改 HTTP 状态。

下面是根据代码构造的失败结构示例，不是一次实机请求的结果：

```json
{
  "ok": true,
  "result": {
    "status": 1,
    "res": "device command failed"
  }
}
```

控制函数正常执行到返回时，内部 `status` 是进程退出状态，`res` 是命令输出；Python 异常时可能只有 `error`。适配器必须检查类型和必需字段，不能把缺少 status 当成 0，也不能仅依据外层 ok 判断完成。

即使 `status=0`，也仅表明程序正常退出；仍须按动作核对设备目标状态。读取 HTTP 失败、JSON 无效、返回 HTML、内层错误、状态缺失和实际结果不明应分别可诊断。

HTTP wrapper 会将 `IsBusyError` 映射为 409，将 `ValidatorError`／`OperationError` 映射为 400，并处理 `HttpError`；未完整读取统一异常 JSON 封装，不在此假定所有错误都有相同 body。控制函数内捕获的异常往往仍落入 HTTP 200。

### 5.2 `/api/node_status`

- 实际调用的是 `nodstatus`，不是 `portstatus`。
- 函数取得退出状态但没有检查，按换行分割输出。
- 每行用 `split(' ')[1]` 取 key，再按整行是否包含 OFF、ON 解析，优先匹配 OFF，否则 N/A。
- 空行、异常格式或错误输出可能导致索引异常或误判；不能假设完整返回 16 个节点。
- 适配器保留 `unknown`，记录采样时间和质量。端口映射尚未可信时不得用其决定向客户开放画面。

### 5.3 `/api/chassis_type`

内部结果包含 `num` 和 `res`。`num=16` 为代码常量，不能证明自动识别了设备型号或端口数。

辅助函数 `__get_node_status()` 调用 `sudo portstatus`，只在退出状态为 0 时解析。其缩写映射为：

| 厂商输出 | JSON 内组合字符串 | 含义 |
| --- | --- | --- |
| `offline` | `OFL` | 连接或通电条件未满足；不能直接等于系统关机 |
| `online` | `ONL` | 连接或通电相关状态 |
| `disabled` | `DSB` | 禁止节点开机 |
| `enabled` | `ENB` | 允许节点开机 |
| 第三个字段 | 原样保留 | 手册示例为 ON／OFF，需验证值域 |

组合格式为 `ONL |ENB |ON` 这样的字符串。函数按非空输出行依次赋键 1、2、3……，没有读取行首实际 `Port N`。缺行或乱序可能造成错位；输出结构不符也可能抛异常。命令失败时返回空对象，不一定带 error。

平台只能将格式、数量、值域不符标为不可信；即使数量为 16，也不能由平台从这个 JSON 还原被固件丢弃的原始端口号。实机映射核验前禁用依赖它的控制；后续可单独评估修补固件解析器，按明确端口号返回结构化数据。该修补不包含在本次任务中。

### 5.4 `/api/chassis_status`

- `chassis_status: "ON"` 写死，不能当成实际机箱电源传感器。
- 命令失败时填入 `error`，同时把 `kvm_status` 置为整数 1；这不是确认选中端口 1。
- 命令成功时取输出按空格拆分后的最后一项，通常为字符串；需去除外围空白后严格解析并检查 1–16。
- 有 error、缺字段、越界、非整数或结果过期，一律按目标未知处理，不颁发控制台访问权。

### 5.5 适配器状态建议

```json
{
  "power_state": "unknown",
  "port_connection": "unknown",
  "port_enabled": null,
  "selected_port": null,
  "observed_at": null,
  "quality": "unverified"
}
```

这是 BarePulse 的规范化状态示例。电源、连接、启用、选中端口和数据新鲜度分开保存；不要用单一“在线／离线”字段混合表达。

## 6. 鉴权与 Nginx

### 6.1 后端认证顺序

只有在路由 `auth_required` 为真且 `auth_manager.is_auth_enabled()` 为真时，认证函数才要求凭据。`exposed_http()` 默认 `auth_required=True`；本次查看的控制函数没有显式关闭它。

| 顺序 | 方式 | 本版静态行为 |
| --- | --- | --- |
| 1 | `X-KVMD-User` + `X-KVMD-Passwd` | 有用户名头就走该分支，失败直接抛错，不回退到 Cookie／Basic |
| 2 | 登录 Cookie | 校验 token 并查用户，失败直接抛错 |
| 3 | `Authorization: Basic ...` | 解码后使用 `.split(':')` 解包；含额外冒号的内容存在兼容性限制 |
| 无凭据 | 无上述方式 | 抛未认证异常，前提是认证开关开启 |

有效认证开关、配置覆盖链、认证后端及实际账号权限尚未核实。基类检查方法为 pass 不代表整个程序无鉴权；子类覆写与 wrapper 调用均已看到。

平台建议以后台请求头认证接入，但必须验证有效配置，且不混传浏览器 Cookie 和认证头。设备密码、token 和 Basic 内容均不得进入客户响应、URL 或普通日志。

### 6.2 Nginx 静态映射

主要配置位于 `/etc/kvmd/nginx/kvmd.ctx-server.conf`。

| 入口／配置 | 已看到的转发 | 认证说明 |
| --- | --- | --- |
| server 层 | `auth_request /auth_check` | 由子请求检查登录状态 |
| `/auth_check` | `http://kvmd/auth/check` | 此 location 自身关闭 auth_request，防递归 |
| `/api`、`/api/...` | 去掉 `/api` 前缀后转 `http://kvmd` | 此层 auth_request off，认证交给 kvmd |
| `/api/ws` | `/ws`，包含 `loc-websocket.conf` | Nginx 子请求关闭，后端鉴权仍应生效 |
| `/api/hid/print` | `/hid/print` | 特殊大请求配置；不代表可匿名 |
| `/api/msd/read` | `/msd/read` | 特殊无缓冲配置 |
| `/api/msd/write_remote` | `/msd/write_remote` | 特殊无缓冲配置 |
| `/api/msd/write` | `/msd/write` | 特殊大请求配置 |
| `/api/log` | `/log` | 特殊无缓冲配置 |
| `/streamer`、`/streamer/...` | 去前缀后转 `http://ustreamer` | 摘录未见本 location 关闭 server 层鉴权；include 完整内容仍需核对 |
| `/redfish` | 原路径转 `http://kvmd` | Nginx 子请求关闭；具体授权语义未单独验证 |

`auth_request off` 关闭的是 Nginx 认证子请求，不等于后端匿名访问。`loc-proxy.conf`、`loc-websocket.conf`、`loc-bigpost.conf`、`loc-nobuffering.conf` 的名称只能作为定位线索，不凭名字假定全部生效参数。

主配置还包含 `/usr/share/kvmd/extras/*/nginx.ctx-*.conf`。这些 extras 内容尚未读取完整，可能影响终端或媒体入口。普通 `/etc/nginx/nginx.conf` 也出现在文件搜索中；当前进程最终加载哪套配置及覆盖关系需以运行基线核对。

之前筛选命令把问号后的文本脱敏，部分 rewrite 正则也一起被遮盖。因此已确认的是路径前缀与上游关系，不能从脱敏结果重建全部查询参数正则。最终网关要验证查询参数、尾斜线、升级连接和大文件行为。

## 7. 手册要求与平台决策

| 手册内容 | BarePulse 处理 |
| --- | --- |
| `portpwron` 开机，`portpwroff` 关机，`portreset` 重启 | 映射到明确的标准动作；实际脉冲、关机与复位结果待核实 |
| `portdisable` 强制关闭并禁止再次开机 | 管理员维护动作，不能包装成普通重启 |
| 禁用后必须 `portenable` 才能再次开机 | 允许开机与实际开机分为两个状态／动作 |
| 启用或禁用后间隔 30 秒再执行后续命令 | 持久化冷却时间；初期按设备级保守调度，不仅前端倒计时 |
| 设备上电后默认允许 16 个端口开机 | 为手册行为，重启后的实际状态重新读取；不依赖旧缓存 |
| 安装系统时不得切换 KVM | 持久化保护占用，不因断线或普通租约到期释放 |
| 刷 BIOS 时不得切换，失败可能导致节点无法启动 | 保护占用覆盖切换、介质和冲突电源动作 |
| ISO 文件不能超过 2G | 仅作为手册版本约束，当前固件与精确字节限制待验证 |
| 支持 flash 镜像和 CD-ROM 模式 | 属于手册描述；实际 API、格式、容量和目标 USB 路径需验证 |
| 无 HDMI 信号时显示彩条 | 显示“无视频信号”；不能当作电源 OFF 或操作系统故障的证明 |
| 分辨率／HDR 可能影响画面 | 作为显示诊断提示；不能为修复花屏而自动重启客户服务器 |
| 关闭 KVM 管理系统后可能需整机重新上电才能恢复 | 不向客户开放 KVM 整机 Power Off／Reboot，避免影响全部端口 |

## 8. 接入风险及处置

| 编号 | 静态发现／证据缺口 | 实现要求 |
| --- | --- | --- |
| K01 | `num` 未校验直接拼接 Shell 命令 | 仅后台绑定生成十进制整数 1–16；拒绝任意客户端端口和目标；设备管理面隔离 |
| K02 | HTTP 200、ok=true 与底层失败可同时出现 | 校验内层字段与类型，分离命令接受、实际完成和目标状态 |
| K03 | 当前目标查询失败时回退到 1 | error 优先，目标未知则阻断控制台 |
| K04 | chassis_status 与端口数量为常量 | 不作为真实传感器或通用自动发现依据 |
| K05 | portstatus 按行序号映射，nodstatus 解析脆弱 | 验证映射与样本完整性，异常不推断；必要时另行修补设备解析 |
| K06 | 控制处理函数中未见设备互斥和操作后等待 | 平台统一调度；厂商二进制是否自带锁仍未知 |
| K07 | async handler 内调用同步 getstatusoutput，未显式设置执行超时 | 可能阻塞事件循环；限制轮询并发，平台超时后不认为设备动作已取消 |
| K08 | 只看到连接列表锁 | 建立平台租约、会话保护和可撤销网关 |
| K09 | Janus 及 extras 路径未全部核对 | 发布前枚举实际媒体入口；能否撤销和阻断直连是验收门槛 |
| K10 | 旧客户仍可能持有视频／键鼠／介质连接 | 确认全部清理前禁止新目标切换和客户分配 |
| K11 | 管理网页或本地实体按钮可绕过平台切换 | 管理流程配合独占，监测目标漂移；检测到不一致立即关闭会话并阻断 |
| K12 | 平台重启或锁过期不等于底层已经空闲 | 恢复时保留保护与未知状态；禁止未经核对接管 |

K01 的防护不能只靠前端校验；后端校验和网络隔离必须同时存在。修复设备源码中的 Shell 调用、结构化状态与错误 HTTP 码可作为独立维护任务；本次不改固件、不部署补丁、不重载服务。

## 9. 驱动和会话实现要求

### 9.1 后台 HTTP 电源驱动

输入为平台已验证的设备引用、绑定版本、标准动作与端口。输出为命令接受状态、设备退出码／脱敏错误、核验状态、时间及证据来源。

步骤为：权限与绑定复核 → 取得设备调度权 → 检查保护／冷却 → 生成固定路径和 num 参数 → 发出一次请求 → 解析返回 → 按允许节奏复核状态 → 更新任务。请求可能已发出但网络超时的情况不可自动重试。

单独读到 ON 无法证明复位已经发生。先明确每种动作的成功证据；只证明命令接受时，页面及 API 要如实表达。不同服务器电源操作是否可以并行，不从“按端口传参”推导，初期串行执行。

### 9.2 控制台网关

服务端租约同时绑定设备、服务器、端口、用户、WHMCS 服务和代次。网关不接受客户端改变端口；只代理批准的路径与事件。全局设备管理 API、Shell、网络和密码修改、机箱电源、任意 ATX／GPIO／Redfish 不能随控制台入口开放。

分配前先完成旧会话撤销与介质清理，再切换并核验目标。视频尚未稳定或目标未知时不向客户发送画面与输入。避免共享缓存及旧快照暴露上一目标；释放时清理按键／鼠标按下状态，防止遗留输入影响下一台。

认证租约到期必须能主动中断已建立的媒体流和 WebSocket。对于 WebRTC，关闭信令不一定意味着已有媒体已结束；必须验证实际会话终止与网络路径。不具备可验证撤销能力的媒体模式暂不向客户开放。

管理员和本地按钮属于带外操作面。平台只能在独占管理流程、目标复核和网络访问控制配合下提供可靠隔离；无法约束的外部切换必须列为上线阻断条件，不能宣称仅凭一个数据库锁就绝对隔离。

### 9.3 保护占用与介质

安装系统／固件维护标记独立于浏览器连接、票据有效期和普通会话超时持久化。客户端重连可在重新鉴权后续接原占用，不能让另一客户抢占。

“释放访问”和“结束保护作业”需有明确业务含义。处于保护中时不能为关闭网页自动卸载镜像；只有明确结束作业或授权处置后才清理和回收。清理失败、设备不可达或挂载状态不明时，设备继续标记不可分配。

## 10. 分阶段验证清单

### 10.1 当前可进行的离线工作

- 根据已有源码构建响应夹具，覆盖退出非零但 ok=true、只有 error、空对象、非法端口、N/A、端口缺行、未知缩写、错误目标回退。
- 模拟重复请求、网络超时、worker 退出、数据库恢复及设备租约冲突。
- 验证网关白名单、后端端口校验、服务归属、票据过期及输入状态清理逻辑。
- 不连接生产设备，不调用所谓只读状态 API 来替代明确的设备测试授权。

### 10.2 后续静态核对的剩余项

仅在实现需要时补充定点读取，不继续无目的遍历设备文件：

- 最终有效认证配置的开关与覆盖关系，避免输出凭据。
- Nginx 完整 include、代理头、WebSocket、视频及 extras 路由。
- Janus／WebRTC、ttyd／Terminal 的入口与网络路径。
- MSD 相关接口的参数与实际挂载状态表示。
- 当前硬件端口映射、固件版本和主板信号接线记录。

### 10.3 明确授权后才做的实机验证

| 项目 | 需要证实的结果 |
| --- | --- |
| 有效认证 | 缺凭据、错误凭据、正确凭据及不同路径符合预期 |
| 状态数据 | 逐端口对应关系，ON／OFF、连接、启用三个维度不混淆 |
| 关机与复位 | 实际行为、时间、失败反馈及完成判定证据 |
| 禁用／启用 | 强制关闭、禁止开机、恢复允许及 30 秒冷却 |
| 控制台切换 | 目标确认、画面刷新、键鼠指向与介质路径一致 |
| 多客户交接 | 旧视频、WebSocket、WebRTC、下载、快照、介质和票据全部失效或隔离 |
| 装机／BIOS 保护 | 掉线、超时、平台重启不会释放占用或切换 |
| 外部切换 | 管理员／实体按钮造成目标漂移时及时阻断访问 |
| 大文件与模式 | ISO 2G 历史限制、flash／CD-ROM、上传中断与清理行为 |
| 并发和故障 | 轮询与控制不会相互阻塞失控；命令超时不重复执行 |

实机验收必须使用明确指定的服务器、端口和测试窗口。测试成功前，客户控制台和有副作用的驱动保持关闭。

## 11. 与上游 PiKVM 文档的关系

[PiKVM 官方 HTTP API](https://docs.pikvm.org/api/) 可作为标准认证与接口设计参考；[官方视频模式说明](https://docs.pikvm.org/video/) 可帮助理解媒体通道。当前上游版本不保证与本台 3.142 定制固件一致。

本项目实际接入依据依次为：本机固件源码和有效配置、对应硬件手册、授权的实机测试记录。官方通用文档不能替代 `/node_status`、`/open_node` 等厂商扩展的本机验证，也不能替代多客户隔离验收。
